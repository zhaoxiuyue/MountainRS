## B1｜大气项：乘性与加性必须分开

**问题.** 7.6 的 objective 写「天空漫射、地形邻接反射及**大气透过率/路径辐射**候选项」，把两者并列。但它们的可辨识性地位完全不同：

```
乘性透过率   rho_hat = T · alpha · mu          T 与 alpha 只以乘积可观测 → 不可分
加性路径辐射 rho_hat = alpha · mu + L_path      L_path 不随 mu 变,alpha 随 mu 变 → 可分
```

7.5 已判 `atmospheric_scale_term`（乘性）为 `non_identifiable_equivalent`，列入 blocked。而路径辐射**从未被判定过**，也未登记——它大概率是可辨识的。

照当前措辞执行，会把一个已被明确阻挡的对象，和一个未经判定但很可能能过的对象，当作同一类东西处理。

**互斥方案：**

| 方案 | 内容 | 代价 |
|---|---|---|
| **A（推荐）** | objective 与 passCriteria 分列二者：加性路径辐射作为新候选走正常登记与资格化；乘性透过率保持 blocked，除非本节点先满足 7.5 给出的三条解封条件之一（独立 AOD 锚点／显式固定 gauge 并声明 alpha 为 gauge-relative／与 alpha 互斥比较且胜出方只取参数化身份） | 无新增成本，只改措辞。7.6 的候选集因此少一项或多一道前置手续 |
| **B** | 本节点完全不碰大气项，只做漫射与邻接 | 最干净，但把大气留给更后面的节点，可能在 7.7 状态激活时再撞一次 |
| **C** | 维持现状不改 | 执行手会在第一次登记大气候选时撞上 7.5 的 blocked 判定并停机，等于把这次裁决推迟到执行期，代价更高 |

**推荐 A。** 理由：加性与乘性的区别是解析可判的，不需要数据；把它写清楚是零成本的，而含糊的代价是执行期停机。

## B2｜新对象登记在哪里

**问题.** 7.6 要引入新对象（漫射项、邻接项、路径辐射及其条件量），但没有定义这些对象的身份登记落点。

7.5 的 `identity-registry-v1.json` 已冻结（`sha256:9725178f…`），不能在 7.6 执行期被追加。7.5 只说了「7.6 候选算子的具体公式与依赖由 7.6 activation preflight 登记，但必须使用 7.5 冻结的类别词表并通过 7.5 的 auditor 校验」——**没说登记物写在哪、与 7.5 registry 什么关系。**

不定义的话，执行手要么去改 7.5 的冻结件，要么另建一套跟 7.5 schema 不兼容的登记。两条都是坏结局。

**互斥方案：**

| 方案 | 内容 | 代价 |
|---|---|---|
| **A（推荐）** | 7.6 建独立的 `operator-identity-registry`，复用 7.5 的 schema 与 auditor，**引用而不修改** 7.5 的 registry | 无。7.5 保持冻结，7.6 自持增量，auditor 一套两用 |
| **B** | 由 7.5 出 `identity-registry-v2`，把 7.6 的候选对象一并纳入 | 违反「7.5 冻结类别体系、7.6 登记候选算子」的分工，且要求 7.5 预先知道 7.6 会加什么 |
| **C** | 不建 registry，候选对象的身份写在算子合同里 | 身份信息散落，auditor 无法统一校验，7.5 建的那套不变量形同虚设 |

**推荐 A。**

## B3｜漫射项必须声明它的地形调制因子

**问题.** 天空可视因子（以及邻接项的张角因子）未在任何 registry 中登记，而**它决定漫射项是物理建模还是经验补偿**：

```
带地形调制  E_dif = E_dif0 · V_sky      V_sky 由 DEM 确定性算出,属 G 的确定性变换、
                                        行为如 E,不新增推断自由度,只加一个散射强度参数
不带调制    rho_hat = alpha·mu + beta   beta 与地形无关,是一个经验截距
```

两者在拟合优度上可能非常接近，**科学含义天差地别**——这正是架构 §1.3 与 7.6 passCriteria 4「单纯降低训练损失不足以 qualified」所针对的情形。

当前 7.5 registry 中不存在任何 sky／diffuse／adjacency 相关对象，7.6 合同也没要求区分这两种形式。

**互斥方案：**

| 方案 | 内容 | 代价 |
|---|---|---|
| **A（推荐）** | 候选登记要求中增加：漫射与邻接候选必须声明其地形调制因子及该因子的身份类别；不含地形调制的常数项**须显式标注为经验补偿**，不得表述为物理机制 | 无新增计算。V_sky 的实际计算成本另计，属执行期工程量，不影响本裁决 |
| **B** | 只允许带地形调制的候选进入本节点，裸截距一律不登记 | 更严，但可能挡掉一个有用的对照基线——裸截距作为对照恰恰能显示地形调制到底带来了多少 |
| **C** | 不作区分 | 极可能出现「加了个截距，误差降了，宣布漫射机制成立」——第三篇教过的坑，原地重踩 |

**推荐 A。** 保留裸截距作为对照，但强制它带上「经验补偿」的身份标签。
